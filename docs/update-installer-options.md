# Windows 自动更新/安装方案选型

本文给出当前可行的开源方案，并说明 Aeterna 当前实现与后续推荐路线。

## 已落地方案（当前仓库）

- 应用内检查更新：在关于页触发，下载 ZSTD 负载包。
- 自动安装：退出旧版后，由 helper 进程执行覆盖安装，再重启应用。
- 升级提示：下次启动进入欢迎页并提示升级成功。
- 用户可下载 EXE 安装器：发布 `aeterna-setup.exe`（Inno Setup 构建）。

优点：
- 与 Flutter/原生 C++ runner 兼容，改造成本低。
- 更新负载统一为 `.tar.zst`，体积和下载效率较好。

限制：
- 仍需你维护更新清单与安装流程联动。

## 开源/成品候选

1. WinSparkle（MIT）
- 定位：Windows 上 Sparkle 风格更新提示框架。
- 适配：适合你保留当前打包系统，只替换“检查更新/提示”层。
- 优点：轻量、原生 UI、跨语言可调用。
- 风险：它不负责你完整打包体系，安装器流程仍需自建。

2. Squirrel.Windows（MIT）
- 定位：安装与增量更新一体方案。
- 优点：安装/更新链路成熟，后台更新能力强。
- 风险：项目活跃度历史波动，接入成本较高；与 Flutter 目录结构整合需要额外封装。

3. NetSparkle（MIT，.NET 生态）
- 定位：可配置的更新框架（支持 appcast、签名等）。
- 优点：更新策略、签名、渠道化能力强。
- 风险：核心生态偏 .NET，Flutter 原生接入需要桥接层。

4. Inno Setup（开源，安装器构建）
- 定位：经典 Windows 安装器构建工具。
- 优点：安装体验成熟，可做 GUI 安装向导。
- 风险：它本身不是完整自动更新框架，需要你配套更新检测逻辑。

## 推荐路线

短期（当前版本）
- 继续使用“自研更新 + ZSTD 负载 + Inno Setup EXE 安装器”方案，先保证稳定交付。

中期（建议）
- 引入 WinSparkle 做更新提示层。
- 保留现有 ZSTD 负载与 helper 安装执行器，减少重构风险。

长期（可选）
- 若要完整安装/升级生态，评估迁移至 Squirrel.Windows 或 Inno Setup + appcast 组合。
